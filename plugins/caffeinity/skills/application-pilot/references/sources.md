# Sources

Where roles come from, and what each one allows. Read the terms themselves before relying on a rule here, since they change: LinkedIn user agreement (`linkedin.com/legal/user-agreement`) and Indeed terms (`indeed.com/legal`), checked October 2026.

## Reading dates honestly

The date on a posting is the only evidence of recency. Record it exactly as shown; if the page says "posted 3 days ago", convert using today's real date and mark it as derived (`2026-10-10 (from "3d ago")`). If nothing is shown, `unknown`.

Never let an undated or stale listing read as new. Sorting by "most recent" on a board is not a date, and boards frequently bump old postings. When filtering to "last 7 days" and a source gives no dates, say the filter could not be applied to that source rather than returning its full list.

## Per-source notes

| Source | What it is good for | Access reality |
|---|---|---|
| Company ATS / careers pages (Greenhouse, Lever, Ashby, Workday) | The authoritative posting, the real apply form, the least contested route | Public listings; applying is done by the user on their own page. Prefer these links in the tracker |
| Referral and network (people the user actually knows, past colleagues) | Highest response rate of any channel | Message drafts only, and only with the user's approval per send |
| Recruiter messages already received | Roles matched to the profile without searching | Read what is in the inbox; never claim a message was read or replied to |
| LinkedIn job search | Volume, and the Easy Apply count recruiters see | Automated access is prohibited by the user agreement, and detection is active, so an agent must not drive it or bulk-apply. Browsing it with the user present, at their pace, is the boundary |
| Indeed and aggregators (Google Jobs, Wellfound, RemoteOK, Hacker News "Who's Hiring") | Breadth, and date filters | Aggregators republish stale listings; resolve each one to the employer's own posting before tracking it |
| Niche boards (sector, region, seniority specific) | Better-fit density per row | Same rules as any public board |

## When there is no browsing tool

A host agent may have no browser, no network, or a site that blocks automation. That is a normal outcome, not a failure. Then:

1. Give the user the exact search URLs to open (one per source, with the filters in the query string).
2. Ask them to paste or drop what they find, including dates where shown.
3. Run modes 3 to 8 on that input, which is where most of the value sits anyway.

Do not work around a block. Do not scrape where the terms or a robots directive say not to, do not rotate accounts or proxies, and do not present a list assembled from memory or search-cache snippets as live openings; that is how stale and fabricated roles get into a tracker.

## Volume reality

The thread this skill descends from claims a few hundred automated applications produced nine interviews in a day. That is not reproducible as a pattern, and the account risk is real: automated submission breaks the terms of the major boards, boards detect it, and employers increasingly screen for generated applications. Say plainly that this skill optimises the reviewed shortlist, and that a fit role with a named referral will beat a bulk spray on response rate for the same hour of effort. If the user still wants high volume, keep the gate: they submit, or they approve each batch while watching.
