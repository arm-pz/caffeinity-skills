# Choosing the first use case

Read this at workflow step 2, after the user has answered the questions.

## Score each candidate 1 to 3 on

| Factor | 3 means |
| --- | --- |
| Payoff | Ties directly to the user's 90-day outcome |
| Repetition | Happens weekly or more, so the team gets used and improved |
| Checkability | A human can judge the output in under 5 minutes |
| Skill fit | Needs only the skills the user has |
| Time fit | Setup fits the user's weekly hours within 7 days |
| Low blast radius | A bad output is cheap to catch before it goes out |

Pick the highest total. On a tie, prefer the one matching the user's "first task off my plate", since motivation decides whether v1 ships.

## Common starters and their usual 3-agent shape

| Use case | Typical team | Watch out for |
| --- | --- | --- |
| Content research and writing | Researcher → Writer → Editor | Hallucinated facts; require sources from the Researcher |
| Lead generation | Prospector → Qualifier → Outreach drafter | Sending at scale; outreach always needs approval |
| Customer support | Triage → Answer drafter → QA reviewer | Wrong answers reaching customers; start draft-only |
| Internal operations | Intake → Executor → Reporter | Vague processes; document the process first |
| Research assistant | Scout → Analyst → Briefer | Unbounded scope; set a question and a deadline |
| Personal productivity | Inbox triage → Planner → Follow-up drafter | Low payoff for business goals; fine for learning |

## Red flags that a use case is wrong for v1

- The output is subjective and the user can't say what "good" looks like.
- It needs integrations the user can't set up within the 7 days.
- A single mistake is expensive: legal, financial or medical advice, or mass sends.
