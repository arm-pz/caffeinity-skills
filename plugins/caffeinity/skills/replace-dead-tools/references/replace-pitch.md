# Writing the replacement pitch

Read this before step 4. One file per list that has at least one confirmed DEAD, ACQUIRED,
SUNSETTING or STALE entry: `outreach/pitches/<slug>-replace.md`. The gap pitch from step 1 stays
where it is. The user sends one or the other, not both.

## Why this one gets answered

An editor whose list sends readers to a parked domain has a problem they didn't know about. Telling
them is useful before you ask for anything, so the evidence comes first and the product second.

## Shape

```
To: <contact_route from lists.csv>            (source: <contact_source>)
Subject: <list title>: <tool> <is no longer live | now redirects to X | is shutting down on DATE>

Hi <first name>,

I was reading "<list title>" and noticed <tool> (#<position>, if numbered) <what the evidence
shows, in plain words>: <evidence_url>.

<If there are more confirmed entries on the same list, one line each, with evidence.>

If you're updating the piece, <Product> covers the same need: <one sentence matched to what the
list said that tool was good for>. Here's an entry in the list's format, in case it saves you time:

> **<Product>**: <40–60 words in the list's entry format>

<Offer from the brief>.

<Signer name>, <role>
```

Body under 120 words, not counting the entry.

## Rules

- Lead with the evidence, and link it. An unlinked claim that a tool is dead reads as a smear.
- Match the replacement to the dead entry's role on the list. If the product doesn't cover that
  need, say so in the report and send the gap pitch instead.
- Only facts from `outreach/brief.md`. No reciprocal-link or payment offers (see the gap pitch
  rules in step 1).
- For SUNSETTING, give the announced date and write "is shutting down", not "is dead".
- For STALE, describe what you saw ("no release since March 2024, and the pricing page returns
  404") and leave the conclusion to the editor.
