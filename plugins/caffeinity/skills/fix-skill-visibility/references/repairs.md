# Repair and verification guide

| Finding | Change | Proof |
| --- | --- | --- |
| Eligibility | Fix an unintended HTTP error, redirect, robots block or noindex at its owning configuration. Preserve intentional exclusions. | Re-fetch the exact intended URL, redirect chain and directives. |
| Canonical | Align the served canonical, sitemap and links with the intended URL. Review intentional consolidation before changing it. | Verify declared signals in the built or live output. Use URL Inspection separately for Google's selected canonical. |
| Discovery | Add the intended page to its manifest or sitemap and add a crawlable link from the most relevant catalog or workflow. | Build and inspect the generated sitemap and the actual anchor source and target. |
| Content | Put the verified task and audience in the title, heading and opening text as appropriate. Keep the branded name and install instructions accurate. | Read the generated title, heading, body and install link. Verify rendered content if JavaScript owns any of it. |
| Ownership | Choose the page that best serves a specific query, differentiate neighboring pages and link to the owner. | Verify the updated page roles and anchors. Measure search overlap later with query and page data. |
| Distribution | Correct the verified GitHub homepage, About text or other listing with the current canonical and accurate description. | Re-read the changed public field. Record a draft or blocked item if the listing is outside the available scope. |
| Measurement | Collect the missing evidence. Preserve queries and filters for comparison. | Record what became observable, with date and source. |

Check redirects and language variants for unintended effects. Keep the baseline measurements. Refresh indexing or request re-crawl only after the changed page is public and eligible.
